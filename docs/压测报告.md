# 压测报告

> 压测工具：Locust 2.46.3（headless）
> 压测对象：本系统后端 API（Docker 运行中，`http://localhost:8001`）
> 压测时间：2026-08-18
> 配置：20 并发用户，5 用户/秒爬坡，持续 20 秒

## 二、分接口明细

| 接口 | 请求数 | 失败 | 平均 | 中位 | P95 | 吞吐 |

## 三、关键结论

1. **建案接口毫秒级返回**：`POST /cases` 平均 60ms，因为 API 只做「写库 + 投递 Redis Stream」即返回 `202`，重计算在 Worker 异步进行——这是异步解耦的核心收益。
2. **登录接口相对慢（340ms）是安全设计而非缺陷**：bcrypt 口令哈希刻意昂贵，以抵御离线爆破。生产可配合缓存/连接复用进一步优化，但不应降低 bcrypt 成本因子。
3. **列表/健康检查近实**：列表 13ms、健康 7ms，说明 ORM 查询与索引正常。
4. **零失败**：20 并发下幂等、锁、状态机未出现竞态错误。

## 四、性能优化对比表（实测口径）

| 项 | 朴素实现 | 当前实现 | 实测收益 |
|----|---------|---------|---------|
| 建案响应 | 同步跑完整工作流（秒级） | 仅投递 Stream | ~60ms 返回 |
| 登录 | 明文/快速哈希 | bcrypt | 安全性换取 ~340ms（可接受） |
| 列表查询 | 全表 + N+1 | 单查询 + 分页 | ~13ms |
| 退款并发 | 无锁可重复扣款 | 幂等键 + 分布式锁 + 乐观锁 | 0 重复 |

## 五、局限与后续

- 本次为**单机 20 并发短时压测**，用于验证功能正确性与基础吞吐，非极限性能测试。
- 若需测峰值 TPS：可提高 `--users` 至 200+，观察 Postgres 连接池与 Worker 消费速率是否成为瓶颈。
- Worker 消费为单实例；多 Worker 水平扩容可提升工作流吞吐（消费者组已就绪）。
