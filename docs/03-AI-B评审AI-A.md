# AI-B 评审 AI-A

> 工程实现型模型评审 `docs/01-AI-A-需求逆向澄清.md`，对照 `docs/00-原始需求.md`。

## 1. 业务目标理解是否正确

正确。AI-A 准确抓住了"从 if-else 硬编码规则引擎重构为多 Agent 协同决策 + Human-in-the-loop + 可审计防重"的核心，且正确识别了"大模型只辅助、金额由确定性规则计算"这一红线。

## 2. 是否遗漏人工审核、超时、重复审批、退款失败

基本覆盖。AI-A 的异常场景表已包含 OCR 超时、置信度过低、模型异常、Redis 不可用、Worker 崩溃、重复审批、退款重复执行。补充一点：**退款执行失败后的补偿**（退款动作成功但状态回写失败、或退款超时）需在决策中明确"终态与退款记录的一致性校验"。

## 3. 是否存在无法实现或成本过高的要求

- "RAG 检索政策合同法规历史案例"被 AI-A 正确降级为"MVP 用规则引擎替代，预留接口"——合理。
- "舆情外部采集"被正确排除出 MVP——合理，避免不可控外部依赖。

## 4. 是否与原始工单冲突

无实质冲突。AI-A 提出的 Q8（三态 vs 七态状态机）确实暴露了工单内部表述不一致，属于必须裁决项，不是 AI-A 的错误。

## 5. 哪些规则还不能进入编码

- 金额阈值、OCR 阈值、欺诈分阈值（未裁决前不能写死）。
- 状态机粒度（三态/七态）未定，直接编码会造成返工。
- 并发审批返回码（409）与"重复审批"语义需锁定。
- "舆情风险"在 MVP 中的具体字段定义未锁定。

## 6. 修改建议

1. 在需求中明确"退款执行失败补偿"策略（建议：退款结果幂等落库，状态与退款记录一致性校验，失败可重试不重复扣款）。
2. 补充"审批意见/驳回理由"字段，前端审批面板需要。
3. 建议把 AI-A 的 Q1-Q8 直接沉淀为裁决表，供人类最终裁决。

**结论：AI-A 需求分析质量合格，仅需人类对 8 个决策问题裁决即可进入规格锁定。**
