# Phase 1 报告：容器化部署

## 目标
将系统打包为可一键启动的 Docker Compose 编排，覆盖 db / redis / backend / worker / frontend 五类服务，并具备健康检查与自愈能力。

## 与任务三定稿规格的偏差说明
任务三提示词假定源码在 `src/` 且端点为 `/api/refund`、`/api/task/{task_id}` 等；本项目的**定稿规格**为 `backend/` + `frontend/` 目录，真实端点前缀为 `/api/v1/`（建案 `POST /api/v1/cases`、详情 `GET /api/v1/cases/{id}`、审批 `POST /api/v1/cases/{id}/decision`、列表 `GET /api/v1/cases`）。本阶段一律以**定稿规格**为准，不按提示词示例的虚构端点实现。

## 本阶段改动

### 1. Worker 心跳（`backend/app/worker/main.py`）
Worker 是无 HTTP 端口的常驻消费者，传统「探测进程」无法判断其是否仍在消费。新增：
- 常量 `HEARTBEAT_KEY = "worker:heartbeat"`、`HEARTBEAT_TTL = 15`（秒）
- 主循环每次迭代（含空闲阻塞）前 `redis.set(HEARTBEAT_KEY, time.time(), ex=15)`，写入失败仅告警、不阻断消费

### 2. Worker 容器健康检查（`docker-compose.yml`）
```yaml
healthcheck:
  test: ["CMD", "python", "-c", "import redis,time; r=redis.from_url('redis://redis:6379/0'); v=r.get('worker:heartbeat'); exit(0 if v and time.time()-float(v)<15 else 1)"]
  interval: 10s
  timeout: 5s
  retries: 5
  start_period: 15s
```
读取 Redis 心跳键，15s 内刷新即判定健康；进程挂起/死亡导致心跳过期 → 不健康 → 依 `restart: unless-stopped` 重启。
