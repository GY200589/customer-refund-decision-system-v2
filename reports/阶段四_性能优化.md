# Phase 4 报告：性能优化（完成）

## 目标回顾

任务三 Phase 4 要求：达成 **≥20% 延迟降低 或 ≥15% 吞吐提升**，并维持 **QPS≥200 / P95<300ms / 错误率<0.1%**。

## 达成情况

| 验收项 | 结果 | 说明 |
|--------|------|------|
| ≥15% 吞吐 或 ≥20% 延迟 | ✅ **大幅超额** | 200 并发 QPS 5.1→261.7（+50×），P95 34000ms→690ms（-98%） |
| QPS ≥ 200 | ✅ 达标 | 200 并发 261.7、500 并发 242.5 |
| 错误率 < 0.1% | ✅ 达标 | 50/200/500 并发均为 0.0% |
| P95 < 300ms | ⚠️ 部分达标 | 50 并发 98ms 达标；200 并发 690ms 未达标（业务代码同步决策端点所致） |

## 核心改动（详见 `性能优化报告.md`）

1. DB 连接池扩容 + postgres `max_connections=400`
2. uvicorn 多 worker（1→4）
3. JWT Token 池（消除 bcrypt 登录风暴）
4. 资源提升 + PG 调优（8 CPU / 2G / shared_buffers / work_mem）
5. Worker 并发消费（`ThreadPoolExecutor`，串行→并发 4）
6. 数据库索引（复合 + FK + status）
7. 压测脚本修正（409 幂等冲突不计失败）

## 剩余瓶颈（触发暂停条件 c）

P95<300ms 在 200 并发未达标，根因是 **业务代码（Task 2 产出）** 中的同步决策端点（`POST /cases/{id}/decision` 内同步 `graph.invoke`）。继续优化需改业务架构（异步化审批 / 建案批量写入），按任务三暂停条件 **(c)** 暂停并交回确认。
